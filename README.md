# Веб-приложение «Интернет-Провайдер» (Provider API & Client UI)

**Учебное** веб-приложение для автоматизации деятельности интернет-провайдера. Проект включает в себя строго типизированный REST API с архитектурным разделением слоев, локализацию (RU/EN) + интерфейс личного кабинета и админ-панели.

## Цели и задачи проекта

### Цель проекта

Выполнить учебное задание и разработать пример масштабируемого, тестируемого веб-приложения, поддерживающего многопользовательский доступ на основе ролей (RBAC), интернационализацию (i18n), интерактивную спецификацию REST API на Sprint Boot + Maven.

### Задачи проекта

Для достижения поставленной цели в ходе проектирования и разработки был успешно решен комплекс следующих задач, разделенных по уровням архитектуры приложения:

#### 1. Системные и инфраструктурные задачи (DevOps & DB)
* **Контейнеризация среды:** Развертывание изолированного окружения и рантайма с помощью технологии Docker и расширения VS Code Dev Containers для изоляции версий Node.js, Java и MySQL от хост-системы.
* **Проектирование реляционной СУБД:** Разработка оптимальной схемы нормализованной базы данных в MySQL.
* **Автоматизация миграций:** Внедрение инструмента Flyway для версионирования схемы данных и автоматического наполнения таблиц тестовыми данными.

#### 2. Задачи серверной части (Backend)
* **Реализация многослойной архитектуры:** Изоляция обязанностей компонентов по enterprise-стандарту: веб-слой (Controllers) - слой бизнес-логики (Services) - слой доступа к данным (DAO) без ORM.
* **Обеспечение безопасности (Security):** Настройка цепочки защитных фильтров Spring Security для аутентификации пользователей по сессиям (JSESSIONID), хэширования паролей по алгоритму BCrypt и защиты от XSS/CSRF-уязвимостей.
* **Разработка ядра биллинга:** Реализация атомарных транзакционных операций (`@Transactional`).
* **Интернационализация и локализация (i18n):** Организация динамического переключения языков ответов бэкенда (RU/EN) на основе считывания HTTP-заголовка `Accept-Language` через `LocaleResolver`.
* **Аудит и логирование:** Интеграция сквозного логирования исключений и действий администратора через SLF4J (Logback).

#### 3. Задачи клиентской части (Frontend)
* **Декомпозиция UI-компонентов:** Разработка отзывчивого интерфейса на React 19 + TypeScript, разделенного на чистые атомарные переиспользуемые модули, полностью внешние по отношению к бизнес-логике.
* **Инкапсуляция рантайм-логики:** Вынос сетевых вызовов API и управления реактивными состояниями в специализированные кастомные хуки React (`useDashboard`, `useAdminPromotions`) .
* **Оптимизация рендеринга:** Применение стандартов React 19 (`Promise.all` и `startTransition`) для параллельного выполнения асинхронных потоков данных I/O, точечной контекстно-зависимой пагинации списков и борьбы с каскадными рендерами.

#### 4. Задачи контроля качества (QA & Docs)
* **Покрытие автоматическими тестами:** Написание модульных и интеграционных тестов с помощью JUnit и Mockito для проверки серверной валидации DTO-моделей, защищенности маршрутов и корректности работы GlobalExceptionHandler.
* **Самодокументируемость кода:** Оформление интерактивной спецификации REST API по стандарту OpenAPI 3 (Swagger UI) и полное документирование Java-классов тегами JavaDoc.

## Технологический стек

### Серверная часть (Backend)
* **Фреймворк:** Spring Boot (Java 26)
* **Безопасность и сессии:** Spring Security (Авторизация на основе ролей, Cookie JSESSIONID)
* **Доступ к данным:** Spring JDBC (`NamedParameterJdbcTemplate`) без ORM
* **Миграции БД:** Flyway Migration
* **Валидация и Локализация:** Jakarta Bean Validation (`@Valid`) + `ResourceBundleMessageSource` (RU/EN)
* **Тестирование:** JUnit 5 (Jupiter), Mockito, MockMvc
* **Документация:** Springdoc OpenAPI 3 (Swagger UI)

### Клиентская часть (Frontend)
* **Среда и язык:** React, TypeScript, Vite
* **Навигация:** React Router
* **Управление состоянием:** React Context API
* **Стилизация:** В стиле Tailwind UI / Shadcn

## Структура базы данных

Реализована реляционная модель в СУБД MySQL. Миграции автоматически накладываются при старте бэкенда через Flyway:

1. **`users`** — Учетные записи. Содержит поля `id`, `username`, `password` (хэш BCrypt), `email`, `role` (`ADMIN`/`CLIENT`), `balance` (`DECIMAL(10,2)`), `is_blocked` и `tariff_id` (Внешний ключ).
2. **`tariffs`** — Тарифные планы провайдера. Поля: `id`, `name`, `price`, `speed_mbps`, `description`, `is_active` (Флаг логической архивации soft delete).
3. **`promotions`** — Маркетинговые акции. Поля: `id`, `title`, `discount_percentage` (1-100%), `end_date`, `description`.
4. **`tariff_promotions`** — Связующая таблица связи **Многие-ко-многим (Many-to-Many)** для привязки акций к конкретным тарифам.
5. **`payments`** — Финансовый аудит. Хранит историю пополнений (со знаком `+`) и списаний лицевого счета (со знаком `-`).
6. **`traffic_stats`** — Пагинированная статистика потребления гигабайт интернета клиентами. Записи уникальны по паре `(user_id, billing_period)` благодаря составному `UNIQUE KEY`.

## Используемые паттерны проектирования

* **Паттерн GoF: Builder (Строитель):** Применен для пошаговой декларативной сборки объектов (например, `User.Builder()`).
* **Паттерн GoF: Command (Команда):** Инкапсулирует административные CRUD-действия над акциями (`UpdatePromotionCommand`, `DeletePromotionCommand`), изолируя бизнес-операции от контроллеров и обеспечивая легкое добавление новых команд безопасности.
* **Паттерн GoF: Strategy (Стратегия):** Реализован на уровне DAO через `RowMapper<T>`.
* **Data Transfer Object (DTO):** Сквозная типизация (`ClientsPageDto`, `ClientDashboardDto`, `ClientTrafficPageDto`) полностью исключает использование сырых неявных `Map<String, Object>` на стыке слоев API и фронтенда.

## Функционал и страницы приложения

Приложение разделено на публичную зону и защищенные маршруты (`ProtectedRoute`) на основе ролей Spring Security. Каждая страница имеет встроенную кнопку мгновенного переключения языков (RU/EN).

### Гость
* **Страница Входа (`/login`):** Авторизация пользователей. 
* **Страница Регистрации (`/register`):** Создание аккаунта нового клиента. Содержит валидацию (FE Validation) на длину полей и формат email.

### Панель Клиента (Личный Кабинет)
* **Страница ЛК (`/dashboard`):** 
  * *Карточка счета:* Выводит текущий баланс, e-mail и поле пополнения средств.
  * *Карточка тарифа:* Выводит детальные характеристики текущего плана. Содержит селектор мгновенной смены тарифа. **Биллинг:** При переходе списывается полная месячная стоимость тарифа. Если баланс меньше стоимости — операция блокируется сервером и выводится точная ошибка нехватки средств.
  * *Карточка акций:* Выводит горячие предложения. Доступна кнопка **Подключить по акции**, которая рассчитывает стоимость с учетом точной скидки, проверяет баланс и списывает сумму.
  * *История финансов и трафика:* таблица учета GB и лог пополнений/списаний.

### Панель Администратора (Панель Управления)
* **Страница Клиентов (`/admin/clients`):** Вывод списка пользователей провайдера с пагинацией. Доступны кнопки мгновенной блокировки аккаунтов и кнопка **«Расход»** для интерактивного начисления израсходованных гигабайт с автоматическим списанием денег с баланса на бэкенде.
* **Страница Тарифов (`/admin/tariffs`):** Список тарифов провайдера и форма добавления новых планов. Доступна кнопка **«В архив»** (Soft delete), переводящая тариф в неактивное состояние.
* **Страница Акций (`/admin/promotions`):** CRUD-интерфейс. Позволяет просматривать список акций, удалять их из СУБД, переводить форму в режим редактирования и объявлять новые скидки.

## Быстрый запуск в VS Code через Dev Containers

Весь проект полностью контейнеризирован. Вам не нужно устанавливать Java, Maven, Node.js или MySQL на свой компьютер.

1. Убедитесь, что у вас запущен **Docker Desktop**.
2. Откройте папку проекта в **VS Code**.
3. Установите расширение **Dev Containers** (от Microsoft).
4. Нажмите `Ctrl + Shift + P` (или `Cmd + Shift + P` на macOS) и выберите команду:
   ```text
   Remote-Containers: Reopen in Container
   ```
5. VS Code автоматически скачает образы, настроит внутреннюю сеть Docker, поднимет базу данных MySQL.

### Запуск Бэкенда (Spring Boot REST API)
Откройте первый терминал внутри контейнера и выполните:
```bash
cd /workspace/server && ./mvnw spring-boot:run
```
Сервер запустится на порту `8080`.

### Запуск Фронтенда (React TS App)
Откройте второй параллельный терминал внутри контейнера и выполните:
```bash
cd /workspace/client && npm run dev
```
Фронтенд запустится на порту `3000`. Откройте в браузере `http://localhost:3000`.

## Запуск автоматических тестов

Проект покрыт модульными и интеграционными тестами. Они проверяют серверную валидацию DTO, логику биллинга, точность BigDecimal-расчетов, защиту маршрутов Spring Security и обработку ошибок в GlobalExceptionHandler.

**Желательно выполнить миграцию перед запуском интеграционных тестов**

Для запуска прогона всех тестов бэкенда откройте терминал контейнера и выполните:
```bash
cd /workspace/server && ./mvnw clean test
```
По окончании консоль выведет подробный отчет и заветный статус `BUILD SUCCESS`.

## Интерактивная документация Swagger

Бэкенд генерирует веб-спецификацию всех доступных API-эндпоинтов на основе метаданных контроллеров и написанных JavaDoc-аннотаций. Пути Swagger добавлены в белый список безопасности.

* При запущенном бэкенде откройте браузер и перейдите по адресу:
  ```text
  http://localhost:8080/swagger-ui.html
  ```
Интерфейс позволяет просматривать структуры входящих/исходящих DTO моделей и тестировать отправку запросов на бэкенд (кнопка *Try it out*) в режиме реального времени.
